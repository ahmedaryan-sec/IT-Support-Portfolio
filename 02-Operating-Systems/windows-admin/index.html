    Procedures

    Open a box and work through its steps — each step ticks off and is remembered. For individual commands, use the tools browser above.

    Tip: press Esc to close a box. Progress is saved in this browser only.

    Writing the Ticket Note

    Issue → Impact → Checked → Action → Result → Status. Fill it in, and the note writes itself.

      How a real support note is built
      
        
      
          
      
            
      ✓ Good note
      
            
      Issue: Print job stuck in the queue.
Impact: One user blocked from printing invoices.
Checked: Printer online, correct printer selected,
         cancel from queue failed.
Action: Stopped Print Spooler, cleared local queue
        with approval, restarted service.
Result: Test page and original document printed.
Status: Resolved. Next step: none.
      
          
      
          
      
            
      ✕ Note that helps nobody
      
            
      Printer not working.
Restarted stuff.
Still not working.

— no model, no error text,
  no checks, no action taken.
      
          
      
        
      
        
        
          
      • Issue — the user's words, in one line.
        • 
          
      • Impact — one user or many, and what work is stopped.
        • 
          
      • Checked — the things you ruled out; this stops the next tech repeating them.
        • 
          
      • Action — exactly what you changed or ran.
        • 
          
      • Result — what happened after, tested with the user where possible.
        • 
          
      • Status / next step — resolved, monitoring, waiting, or escalated and why.
